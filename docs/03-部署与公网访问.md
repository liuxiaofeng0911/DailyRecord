## 1. 已确认方案

- 前端容器端口只绑定宿主机 `127.0.0.1:9110`。
- 宿主机运行 `cloudflared.exe`，回源到 `http://127.0.0.1:9110`。
- 公网只经 Cloudflare Tunnel + 自有域名 + HTTPS，不开放路由器端口。
- Immich 不反代到公网；缩略图/原图由后端 API 代理。
- 每个应用账号自动开通独立 Immich 用户与 API Key，照片库按账号隔离。
- OWNER 配置一次 Immich 管理员 Key；新用户注册后全自动开通，无需逐人操作。
- PostgreSQL、Redis、Immich 只在内网或宿主机本机可达。

## 2. 目标拓扑

```
公网
  │ HTTPS
Cloudflare（TLS / WAF / 可选 Access）
  │ 出站长连接（无需端口映射）
cloudflared.exe（宿主机）
  │ http://127.0.0.1:9110
web:9110（nginx + 前端）
  ├─ api:9111（FastAPI）
  │    ├─ postgres:5432（内网）
  │    ├─ redis:6379（内网）
  │    └─ Immich API → host.docker.internal:2283
  │         ├─ 管理员 Key：仅开通/修复
  │         └─ 用户 Key：日常上传/读取
  └─ 无 /immich/ 公网反代
```

## 3. 端口规则

| 服务 | 端口 | 暴露方式 |
|---|---|---|
| web | 9110 | 仅宿主机 `127.0.0.1` |
| api | 9111 | 仅 Docker 内网 |
| postgres | 5432 | 仅 Docker 内网 |
| redis | 6379 | 仅 Docker 内网 |
| immich | 2283 | 宿主机本机/内网，不对公网 |
| cloudflared.exe | 无 | 只建立出站连接 |

Compose 必须写成：

```yaml
ports:
  - "127.0.0.1:${WEB_PORT:-9110}:9110"
```

禁止使用 `"9110:9110"`；Windows 防火墙额外拒绝 9110 入站。

## 4. 首次部署

```bash
# 1. 准备
git clone <repo> /opt/dailyrecord   # Windows 下为项目目录
cd /opt/dailyrecord
cp .env.example .env

# 2. 填写 .env（最小集）
# POSTGRES_PASSWORD、JWT_SECRET、RSA_PRIVATE_KEY、RSA_PUBLIC_KEY
# IMMICH_URL=http://host.docker.internal:2283
# CREDENTIAL_ENCRYPTION_KEY=<32 字节 Base64，加密管理员 Key 与用户 Key>
# 生成：python -c "import base64,os;print(base64.urlsafe_b64encode(os.urandom(32)).decode())"
# MAX_UPLOAD_MB=100
# TZ=Asia/Shanghai、ENV=prod
# CORS_ORIGINS=https://diary.example.com

# 3. 构建并启动
sh scripts/build.sh --check

# 4. 本机验证
curl -fsS http://127.0.0.1:9110/healthz
```

首次打开 `http://127.0.0.1:9110` 注册第一个账号，自动成为 OWNER；确认注册模式已切为 CLOSED。

然后以 OWNER 进入"系统设置 → Immich 自动开通"：

1. 填入 Immich 地址（默认 `IMMICH_URL`）。
2. 填入 Immich 管理员 API Key（建议使用专用的开通管理员账号），只授予 `adminUser.create`、`adminUser.update`。
3. 测试连接并启用，设置自动开通配额（默认 20）。
4. 点击"为已有用户补开通"，先给 OWNER 自己开通照片库。
5. 之后通过邀请码注册的新账号会自动创建独立 Immich 用户与 API Key。

不再需要 `IMMICH_UPSTREAM`：nginx 不反代 Immich，前端也不再直连 `/immich/`。

## 5. 宿主机 cloudflared

```powershell
# 安装与登录
cloudflared.exe tunnel login
cloudflared.exe tunnel create dailyrecord
cloudflared.exe tunnel route dns dailyrecord diary.example.com
```

`%USERPROFILE%\.cloudflared\config.yml`：

```yaml
tunnel: <TUNNEL_UUID>
credentials-file: C:\Users\<用户>\.cloudflared\<TUNNEL_UUID>.json
ingress:
  - hostname: diary.example.com
    service: http://127.0.0.1:9110
  - service: http_status:404
```

启动与开机自启：

```powershell
cloudflared.exe tunnel run dailyrecord
# 或注册为 Windows 服务（需管理员）
cloudflared.exe service install
```

Cloudflare 侧必须设置：

- 全域名启用 Access（邮箱 OTP 或 SSO）；应用登录仍保留。
- WAF 速率限制；关闭 `/api` 缓存；开启 Always Use HTTPS。
- 账号强制 2FA；Tunnel 凭据只留在本机，不提交仓库。

## 6. Immich 后端代理与账号隔离

- 删除 nginx 的 `location /immich/`。
- 后端新增 `GET /api/immich/thumbnail/{assetId}`，按当前账号凭据取图，要求登录。
- 前端 `immichThumb()` 改为 `/api/immich/thumbnail/{assetId}`。
- 资产列表与导入继续走 `POST /api/immich/assets`、`POST /api/immich/import`，均使用当前账号凭据。
- 代理只返回图片流，不暴露 Immich 管理页面、API Key 和内部地址。
- 全自动开通（新账号注册后）：
  1. 后端用管理员 Key 创建独立 Immich 用户（邮箱取应用邮箱）。
  2. 用临时密码登录一次，创建最小权限用户 Key（asset/album，不含管理员权限）。
  3. 创建默认相册后，把 Immich 密码重置为新的随机值并丢弃。
  4. 用户 Key 用 AES-256-GCM 加密存储；应用不保存 Immich 密码/token。
  5. 账号设置显示"照片库正常"，用户无需手动绑定。
- 失败处理：
  - Immich 不可用：账号可用，照片库 `failed`，后台自动重试 3 次，OWNER 可手动补开通。
  - 同邮箱已存在 Immich 用户：标记 `failed`，不接管、不删除。
  - 管理员 Key 未配置/失效：回退手动绑定，文字记录不受影响。
- 安全约束：
  - 仅 INVITE 注册或 OWNER 创建账号触发自动开通；OPEN 注册默认不触发。
  - 管理员 Key 只授予 `adminUser.create/update`，与用户 Key 使用不同 AAD 加密。
  - 临时密码只在内存，禁止日志/审计/接口返回；开通后立即重置失效。
  - 自动开通配额默认 20，按账号/IP 限流。

## 7. 更新与备份

```bash
# 指定版本号（位置参数与 --version 等价）
sh scripts/build.sh 1.2.3 --check
sh scripts/update.sh --version 1.2.3

# 不指定版本号：默认取当前版本的下一个补丁版本 X.X.(X+1)
sh scripts/update.sh
sh scripts/version.sh --next        # 查看下一个版本号

sh scripts/backup.sh                # 建议每天 03:00
sh scripts/restore.sh backups/<时间戳>
```

版本规则：

- 当前版本保存在仓库根目录 `VERSION`（如 `0.1.0`）；构建成功后写回新版本。
- 镜像标签为 `dailyrecord-api:<版本>` 与 `dailyrecord-web:<版本>`，同时 `APP_VERSION` 写入 `.env`，便于 `docker compose` 直接复用。
- 后端 `GET /health` 返回 `version`；前端"账户设置"显示同一版本号。
- 回滚时指定旧版本号重新构建：`sh scripts/update.sh 1.2.2`。

备份必须包含：

- PostgreSQL：`pg_dump -Fc`
- 上传文件：Docker 卷 `apidata`（当前脚本未覆盖，待修正）
- 配置：`.env`、`docker-compose.yml`
- `CREDENTIAL_ENCRYPTION_KEY`：必须单独离线保存；丢失后所有 Immich Key 无法解密
- 照片原图：由 Immich 自己的备份负责

## 8. 验收

```powershell
# 前端存活
curl.exe -fsS http://127.0.0.1:9110/healthz

# 只应看到 127.0.0.1:9110
netstat -ano | findstr :9110

# 公网访问
curl.exe -I https://diary.example.com

# 从另一台机器直连源站应失败
curl.exe --connect-timeout 3 http://<宿主机IP>:9110

# Immich 不应能从公网访问
curl.exe -I https://diary.example.com/immich/
```

通过标准：

- 域名可访问，HTTP 自动跳转 HTTPS。
- 宿主机 IP 的 9110 不可达。
- `/immich/` 公网返回 404。
- 无 Token 调 `/api/entry/list` 返回登录失效。
- 登录连续失败触发限流/锁定。
- 101MB 上传被拒绝，100MB 以内成功。
- 邀请码注册新账号后，无需人工操作，账户设置显示照片库正常。
- A、B 自动开通后，B 搜索不到 A 的照片；B 用 A 的 assetId 取缩略图返回 404。
- Immich 停止时注册，账号可用且照片库失败；恢复后重试成功。
- 数据库中无明文 Immich 密码/token/API Key，日志与接口响应同样无明文。
